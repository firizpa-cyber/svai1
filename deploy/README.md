# Деплой сайта на Ubuntu-сервер

Разворачивает Nuxt-сайт (`node .output/server/index.mjs`) под управлением **PM2**
за обратным прокси **Nginx**. Сборка идёт на сервере, поэтому нативные модули
(sharp и т.п.) собираются корректно.

> NestJS-бэкенд (`backend/`) в продакшене **не запускается** — это заготовка,
> а реальный API сайта лежит в `server/api/*` внутри Nuxt.

## Что нужно

- Сервер Ubuntu 20.04/22.04/24.04 с доступом по SSH (IP + пользователь + пароль или ключ).
- На вашем компьютере (Windows) — **Git Bash** (входит в [Git for Windows](https://git-scm.com/download/win)).
  В нём есть `ssh`, `scp`, `tar` — больше ничего ставить не надо.
- Если есть домен — направьте его A-запись на IP сервера (для HTTPS).

## Шаги

### 1. Заполните данные сервера

```bash
cp deploy/config.env.example deploy/config.env
```
Откройте `deploy/config.env` и впишите `SERVER_HOST`, `SERVER_USER`, при входе
по ключу — `SSH_KEY`, а также `DOMAIN` и (по желанию) `LETSENCRYPT_EMAIL` для
бесплатного SSL.

### 2. Проверьте подключение (необязательно)

```bash
./deploy/connect.sh
```
PowerShell-вариант: `.\deploy\connect.ps1`

### 3. Запустите деплой

```bash
./deploy/deploy.sh
```

Скрипт сам:
1. зальёт исходники на сервер (без `node_modules`/`.output`/`.git`);
2. при первом запуске поставит Node 20, PM2, Nginx, настроит firewall и (если задан email) SSL;
3. установит зависимости, **соберёт** Nuxt и запустит сайт через PM2;
4. пропишет автозапуск PM2 после перезагрузки сервера.

После завершения сайт доступен по адресу сервера / вашему домену.

## Обновление сайта

Повторно запускайте тот же скрипт — он перезальёт код, пересоберёт и
перезапустит без простоя (`pm2 startOrReload`):

```bash
./deploy/deploy.sh
```

## Полезные команды на сервере

```bash
pm2 status            # статус приложения
pm2 logs svai         # логи в реальном времени
pm2 restart svai      # ручной перезапуск
sudo nginx -t         # проверить конфиг Nginx
sudo systemctl reload nginx
```

## ⚠ Про секреты

Файл `.env` (SMTP-пароль и пр.) **заливается на сервер** — он нужен сайту в
рантайме для отправки писем о заказах. На самом сервере он лежит в `APP_DIR/.env`.
Если не хотите хранить SMTP-пароль в репозитории/архиве — после первого деплоя
отредактируйте `.env` прямо на сервере и выполните `pm2 restart svai`.
Сейчас в `.env` лежит реальный пароль приложения Gmail — рекомендую его
**отозвать и перевыпустить** после настройки, раз он уже был в открытом виде.
